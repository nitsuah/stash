## Improvement suggestion for `agent/prompts/METRICS.md`

The spec at `agent/prompts/METRICS.md` is written entirely around a local Windows checkout
(`C:\Users\<user>\code\<repo>`) and Docker (`docker compose run --rm unit`, coverage "in Docker,
prefer Docker so no host toolchain is required"). It has no cloud-native fallback: no guidance
for a fresh clone in an ephemeral container, and no instruction for running `npm`/`pip`/`mvn`
directly when Docker isn't present. This run had to improvise the native equivalents (documented
in the scheduled task prompt, not in METRICS.md itself). Recommend updating METRICS.md to
document both paths explicitly — Docker for local runs, native package-manager commands for
cloud/CI agents — so a future run doesn't have to re-derive this each time.

A second, smaller gap: METRICS.md's Step 1 assumes a pre-existing local checkout ("Confirm the
local checkout ... is on its default branch"). A cloud run has no such checkout and must clone
fresh each time; the spec should say so rather than assuming step 1 always applies.
