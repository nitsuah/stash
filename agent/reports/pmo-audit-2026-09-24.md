## 3. Verified findings: doc/reality contradictions

Ranked by severity.

1. **osrs: Docker build broken on `main` (P0).** `docker build` fails with `No matching distribution found for numpy==2.5.3`, because 2.5.x requires Python ≥3.12 and both Dockerfile stages use `python:3.10-slim-bookworm`.
   - Dependabot #41 (2026-09-23) passed CI because #42 moved CI to 3.12 the same day.
   - The README still says "Python 3.10 is the single supported version, used consistently in CI, Docker…". That is now false.
   - There is no Docker build check in CI.
2. **deployer: security gate is a no-op.** The CI `slither` job (run 35902436895) is `success` but logs `No contract was analyzed … 0 contracts with 102 detectors`. It also has `continue-on-error: true` and `fail-on: none`, so it can't fail. Meanwhile README claims "✅ Configured Slither static analysis". The likely cause is `hardhat_ignore_compile: true` combined with the Hardhat v3 artifact layout. That cause is unverified and labeled as such in the PR.
3. **games: coverage misreported by 34 points.** METRICS says 95.41% "Docker-validated", but Docker `npm run test:coverage` gives 61.09% statements and exits 1 against the 75% threshold.
   - The whole gap is `lib/tank/TankGame.jsx`: 837 lines at 0%, added in #284 on 2026-08-07 and not in the coverage excludes.
   - CI runs `test:ci` without coverage, so this is invisible there.
4. **fire: coverage threshold failing, CI blind to it.** Branch coverage is 68.68% against a 70% gate (METRICS: 70.13%, "Met"). CI runs `npm test` only. The Docker `test` image also can't write `/app/coverage` (EACCES: `WORKDIR /app` is root-owned, then `USER node`).
5. **overseer/vigil: TASKS checkboxes out of sync.** Six items had "✅ SHIPPED" in their body but `- [ ]` boxes. I verified all six in code or on GitHub. Three more "SHIPPED" items only partly meet their acceptance criteria:
   - zombie-branch: bulk-delete UI missing
   - dependency graph: 2D, not the specified 3D
   - tech-debt trending: still open
6. **overseer/vigil: duplicate planning docs.** `docs/TASKS|ROADMAP|METRICS|FEATURES.md` are June–August copies that shadow the current root files. `lib/sync.ts` reads the root first, so they are dead but misleading.
7. **Same failure mode in games, fire and osrs:** CI doesn't run the command the docs call authoritative (coverage run or Docker build), so breakage merges green. This is worth a portfolio-level rule. See §5.
8. **Stale METRICS counts** in gcp, skyview, nitsuah-io and osrs: test counts grew 9–62 since the last measurement. These are corrections, not regressions.
9. **kryptos:** the backend's move to Render (2026-09-06) wasn't documented anywhere. Both endpoints were verified live: Netlify returned 200 in 0.5s, and Render `/health` returned 200 in 22s cold.
10. **darkmoon:** open issue #446 isn't tracked in TASKS, and METRICS issue counts date to "Mar 2026".

## 5. Risks, assumptions, unknowns

- **Not measured, left as TBD:** E2E and Playwright counts (vigil, games, skyview, nitsuah-io), Lighthouse, bundle size, and osrs coverage (image doesn't build).
- **fire coverage was measured with `-u root`**, a workaround for the image permission bug. The test code and config are unchanged, so I treat the numbers as valid, and the PR says so.
- **The gcp coverage method matters:** a non-editable `pip install .` makes coverage report 0%. My first run hit this. The rerun used `-e .`.
- **Pattern to raise with [[RSI]]:** three repos (games, fire, osrs) have "authoritative" commands that CI never runs, and Dependabot merges are the typical way they break (osrs was broken within the same day). A portfolio rule of "CI must run whatever METRICS.md cites as its source" would have caught all three.
- **Side effects of repo hooks:** darkmoon's pre-commit hook started a `darkmoon-solo` container, which is still running (repo-owned mechanism, not stopped). The games and nitsuah-io pre-push hooks ran test suites on the host. I removed the three compose networks I created (`vigil-pmo_default`, `skyview-pmo_default`, `avatar-pmo_default`).
