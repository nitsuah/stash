## Auto-merge deviation (important — read before relying on this routine to self-merge)

`METRICS.md` step 7 instructs this routine to auto-merge a docs-only, all-green PR without
human review. In this run, the session's own permission layer (an "auto mode classifier")
**denied** the `Agent` dispatch outright with reason `Merge Without Review` for 3 of the first 5
per-repo tasks — before any coverage work even started — because their instructions included an
autonomous-merge step. This is a platform-level guardrail, not a bug to route around.

Response: all 5 PRs were redispatched (or amended in-flight) with the merge step removed
entirely. **Every PR from this run (fire#112, vhs#56, overseer#223, auto-apply-plugin#65,
skyview#138) was left open and non-draft for human review — none were auto-merged**, regardless
of CI outcome, even where all checks passed (auto-apply-plugin's did). This is a deliberate
deviation from `METRICS.md`'s written auto-merge rule, made because the environment itself
refuses to allow the action, not because CI was red or the diffs were unsafe. Future runs in this
same cloud environment should expect the same block and plan to leave PRs open rather than retry
the merge.

## Process note

## Improvement suggestions for `agent/prompts/METRICS.md`

1. **Still no cloud-native fallback documented**, despite two prior cloud runs (2026-09-04,
   2026-09-11) plus this one having had to improvise native npm/vitest/jest commands in place of
   step 3's Docker-first instructions. The scheduled task prompt itself now carries this
   knowledge (it explicitly told this run to use native commands per language/framework), but
   `METRICS.md`'s own Step 3 still reads "prefer Docker so no host toolchain is required" with no
   native equivalent spelled out per repo. Recommend documenting both paths directly in
   `METRICS.md` (Docker for local runs, native package-manager commands for cloud/CI agents) so
   this doesn't have to be re-derived or carried externally in the scheduling prompt each time.
2. **New this run:** `METRICS.md` step 7's auto-merge rule has no fallback for an environment
   that outright disallows autonomous merging (see deviation note above). Recommend adding
   explicit language: "if the environment's own permission policy blocks unattended merging,
   leave the PR open and non-draft for a human — this is not a failure to retry."
3. Step 1 still assumes a pre-existing local checkout ("Confirm the local checkout ... is on its
   default branch") — a cloud run clones fresh each time and has no such checkout. Same gap noted
   in the 2026-09-04 report; still unaddressed in the spec file itself.
