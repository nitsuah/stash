One issue. One small PR.

An imp is a headless Claude worker, routed through 9router, that takes exactly one GitHub issue and opens one small pull request. The model never pushes and never holds a GitHub token. A deterministic gate — Docker tests, a line budget, path allow/deny lists, and a Co-Authored-By trailer — decides whether the work becomes a PR.

How it works

Queue → gate → PR → review / fix

GitHub issues are the queue. Labels are the state machine. The hourly dispatcher has no model of its own: it picks work, runs the kit, and writes the ledger.

One warlock per machine, many imps per machine, many machines. The warlock is the single dispatch.mjs cycle; the imp-runner is the detached checkout it executes; imps are the workers. More throughput means more imps (--concurrency), never a second warlock — two would see the same imp:ready labels, pick the same briefs, and race on one imp-nm-<repo> volume. Machines coordinate only through labels. Contract: WARLOCK.md, checked by node <kit>/imps/warlock.mjs.

Brief human / triageNewest issue comment starting with <!-- imp-brief --> wins. Front matter is taken verbatim. The runner substitutes {wt} and runs test: itself — the model's "tests pass" claim is never trusted.
Dispatcher 0 tokensdispatch.mjs hourly: lock file, 9router MAX health probe, fix-sweep open imp PRs first, then pick quiet repos (prefer bot:review), respect WIP / per-repo / daily caps, pause a repo 24 h after two straight gate failures.
Worker AI · one issueimp.mjs run through 9router with PATH + router URL/key only. Tools: Read, Edit, Write, Glob, Grep, a short git allowlist, docker run. No gh, no host npm.
Gate deterministicTests and optional lint: in Docker, at least one commit, Co-Authored-By: …imp on every imp-authored commit, no leftovers, size and scope checks, hard deny of .github/, .env*, secrets/, lockfiles.
PR / review / fix AI · boundedAfter a pass, imp.mjs pr pushes and opens the PR. review.mjs posts a read-only COMMENT review (verdict recomputed from findings). fix.mjs answers threads and red CI for at most two rounds.
Labels: imp:ready → imp:working → imp:pr or imp:failed. Exhausted fix rounds or a conflict get imp:needs-human. The kit can arm squash auto-merge when the reviewer verdict is approve and checks look green — branch rulesets still apply, so required status checks are what actually stop a red merge.
Guardrails

The model is nondeterministic. The rails are not.

Everything that can be a script is a script. Caps live in code defaults (see dispatch.mjs / lib.mjs), not in wishful docs.

Machine setup

A detached runner, never a copy inside the repo

The kit lives in the public nitsuah/.github imps/ tree (same pattern as journeys). Each machine keeps a detached checkout outside any project tree, so the hourly task can reset it to origin/main and only merged kit code runs unattended.

Detached checkout

Rebuild locally (often named imps-runner), register the Windows scheduled task that runs the hourly wrapper, and point stash at it with IMPS_KIT_PATH or ignored .imps/kit-path.txt. Prefer the kit's setup script when present; otherwise follow STANDARD § Scheduling.

stash wrapper

scripts/imp-run.ps1

Thin resolver: config → local kit path → node <kit>/imps/imp.mjs …. Repo config stays in .github/imps-config.yml; secrets and absolute paths stay off git.

State lives under a machine-local home (default ~/.imps): runs.jsonl, dispatch.jsonl, briefs and transcripts. Paths and tokens never belong in the Pages site or the public repo.
Self-improvement

Measure the runs. Teach the preamble.

Every run writes a ledger row (model served, turns, tool errors, gate reasons, tokens). That is the training data for the next prompt change — not vibes.

Reportnode imps/imp.mjs report (and stats.mjs) surfaces recurring tool-error kinds and gate failures.
One lessonEach recurring failure becomes one line under "Lessons from earlier runs" in PREAMBLE.md, or one gate rule in lib.mjs, citing the run ids. Same loop for REVIEW.md and FIX.md.
Own PRShip the lesson alone so the brief hash changes and the next batch shows whether it helped. Delete a lesson once ~10 runs pass without hitting it.
Token reviewWeekly: can a script or a free model do the paid triage step? Move one thing per review into the kit (precheck.mjs is the template).
Cost-aware loop

Journeys find. Imps fix. Journeys verify.

Nightly journeys cost zero tokens and file bot:journey issues with screenshots and a Docker repro. Imps are for the small, already-diagnosed fixes (often bot:review first). Green nights after the merge are the verification — the bot closes the issue, not the author.
